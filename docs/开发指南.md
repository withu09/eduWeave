# 开发指南

> 面向接手后需要继续开发的同学。假设你已完成 [部署说明.md](../部署说明.md) 的环境安装。

---

## 一、开发环境启动

推荐两个终端分别跑前后端，中间件用 Docker 常驻：

```bash
# 终端 0：中间件
docker compose up -d eduweave-redis eduweave-chroma eduweave-postgres

# 终端 1：后端（热重载）
cd backend && uvicorn main:app --reload --port 8000

# 终端 2：前端（HMR）
cd frontend && npm run dev
```

---

## 二、代码约定

### 后端

- **分层**：路由只做参数校验与响应组装，业务逻辑放 `agents/` 或 `utils/`
- **异常**：Agent 调用必须 `try/except` 并有降级分支，不允许让异常穿透到 SSE 流
- **配置**：所有可变量从 `app/core/config.py` 的 `settings` 读取，禁止散落 `os.getenv`
- **密钥**：只从环境变量读取，**任何情况下不写进源码**

### 前端

- **组件**：`components/` 放视图与业务组件，`components/ui/` 放无业务逻辑的原子组件（Radix 封装）
- **状态**：跨视图共享用 `store.ts`（Zustand），视图内部用 `useState`
- **样式**：Tailwind 原子类 + `styles/theme.css` 的 CSS 变量，不写内联样式
- **接口**：统一走 `import.meta.env.VITE_API_URL`，当前部分文件仍有硬编码，改动时顺手替换

## 三、新增一个 Agent

四步走。

**第 1 步** — 在 `backend/app/agents/` 新建文件，例如 `translator.py`：

```python
from pydantic import BaseModel
from pydantic_ai import Agent, RunContext
from app.agents.orchestrator import spark_model
from app.agents.deps import AgentDeps
from app.utils.telemetry import log_thought, set_agent_status

class TranslatorOutput(BaseModel):
    translated: str
    notes: str = ""

translator_agent = Agent(
    model=spark_model,
    deps_type=AgentDeps,
    output_type=TranslatorOutput,
    system_prompt="你是学术翻译助手，把输入翻译为规范中文。",
)

@translator_agent.tool
async def get_glossary(ctx: RunContext[AgentDeps], term: str) -> str:
    """查询术语表（示例：从 ChromaDB 检索）。"""
    await log_thought(f"查询术语：{term}")
    return "..."
```

**第 2 步** — 在 `agents/__init__.py` 导出（如需）。

**第 3 步** — 在 `main.py` 或某个 router 中调用：

```python
from app.agents.translator import translator_agent

@app.post("/api/translate")
async def translate(text: str):
    await set_agent_status("Translator", "working")
    try:
        ctx = await translator_agent.run(text, deps=deps)
        return ctx.output.model_dump()
    finally:
        await set_agent_status("Translator", "idle")
```

**第 4 步** — 如果前端控制台要显示这个 Agent，在 `ConsoleView.tsx` 的 Agent 列表里加上「Translator」。

## 四、新增一个 API 路由

1. 在 `app/routers/` 新建文件或用现有文件
2. 定义 `router = APIRouter(prefix="/api/xxx", tags=["XXX"])`
3. 在 `main.py` 中 `app.include_router(xxx_router)`
4. 访问 `/docs` 确认已注册

---

## 五、新增一个前端视图

1. 在 `frontend/src/app/components/` 新建 `XxxView.tsx`
2. 在 `App.tsx` 的 `view` 类型联合中加入 `"xxx"`
3. 在 `<main>` 内加条件渲染：`{view === "xxx" && <XxxView />}`
4. 在 `Sidebar.tsx` 的 `ITEMS` 与 `MobileNav` 中加入导航项

## 六、调试技巧

### 看 SSE 流

```bash
curl -N "http://localhost:8000/api/chat?user_input=测试"
```

### 看 Spark 原始请求/响应

`SparkCompatTransport` 已内置打印，后端控制台会输出：

```
[SparkCompatTransport] Request: POST https://...
[SparkCompatTransport] Request Body: {...}
[SparkCompatTransport] Response Status: 200
[SparkCompatTransport] Raw Response Body: {...}
```

### 看 Agent 遥测

```bash
# 订阅 Redis 频道
docker exec -it eduweave-redis redis-cli SUBSCRIBE agent_telemetry
```

### 定位前端接口错误

浏览器 DevTools → Network → 筛选 `Fetch/XHR` 与 `WS`，关注 `/api/chat` 的 EventStream 分帧。

## 七、测试现状

当前 `backend/test_*.py` 是**手工联调脚本**（直接 `python test_chat_agent.py` 运行并打印结果），不是自动化测试：

| 脚本 | 验证内容 |
| --- | --- |
| `test_chat_agent.py` | Chat Agent 基础调用 |
| `test_agent_stream.py` | Agent 流式输出 |
| `test_spark_stream.py` | 星火 WebSocket 流式连通性 |
| `test_kb_mermaid.py` | Mermaid 生成 |
| `test_starmap_api.py` | 星图接口 |

**建议的改进**：引入 `pytest` + `httpx.AsyncClient`，用 `TestClient` 覆盖路由，用 mock 替换 `spark_model` 避免真实调用产生费用。
