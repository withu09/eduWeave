# 架构设计

> EduWeave AI 后端为 FastAPI + PydanticAI 多智能体架构，前端为 React + Vite 单页应用。

---

## 一、整体分层

```
┌───────────────────────────────────────────────────────────────┐
│  接入层                                                       │
│  main.py:  REST · SSE · WebSocket · CORS · lifespan 钩子       │
├───────────────────────────────────────────────────────────────┤
│  路由层  app/routers/                                          │
│  kb.py（知识库 19 个接口） · starmap.py（星图百科） · tts.py      │
├───────────────────────────────────────────────────────────────┤
│  编排层  app/agents/                                           │
│  orchestrator ──▶ chat ──▶ profiler / writer / examiner / …    │
│  starmap_agents ──▶ default / inquirer / pro                   │
├───────────────────────────────────────────────────────────────┤
│  支撑层  app/                                                 │
│  core/config · schemas · db · services · utils                 │
├───────────────────────────────────────────────────────────────┤
│  外部依赖                                                      │
│  讯飞星火 · 讯飞 TTS · Dify · Redis · ChromaDB · PostgreSQL    │
└───────────────────────────────────────────────────────────────┘
```

依赖方向严格自上而下，下层不反向引用上层（`deps.py` 仅依赖 schema 与 orchestrator 的模型定义，属例外但可接受）。

## 二、Agent 协作模型

### 2.1 依赖注入

所有 Agent 通过 `AgentDeps`（dataclass）获取共享上下文：

```python
@dataclass
class AgentDeps:
    chroma_client: Any              # 向量检索客户端
    student_profile: StudentProfile # 本轮学情画像
    study_plan: Optional[StudyPlan] = None   # 由 Chat Agent 写入
    node_title: Optional[str] = None         # 当前节点标题
```

`AgentDeps` 是**可变**的：Chat Agent 调用 `recommend_plan` 工具后把 `StudyPlan` 写回 `deps.study_plan`，`main.py` 随后读取它决定是否推送星图节点。这避免了额外的返回值通道。

### 2.2 单轮对话时序

```
Client                FastAPI              Profiler      Chat        Writer
  │                      │                    │            │           │
  │ GET /api/chat        │                    │            │           │
  │─────────────────────▶│                    │            │           │
  │                      │ yield "0:分析中"   │            │           │
  │◀─────────────────────│                    │            │           │
  │                      │─── run(profile) ──▶│            │           │
  │                      │◀── StudentProfile ─│            │           │
  │                      │                    │            │           │
  │                      │─── run_stream(deps=profile) ────▶│           │
  │                      │◀════════ 流式文本增量 ══════════│           │
  │◀─── "1:{chunk}" ─────│                    │            │           │
  │  ...                 │                    │            │           │
  │                      │◀══ deps.study_plan 被写入 ═════│           │
  │                      │─── run(deps) ─────────────────────────────▶│
  │                      │◀── {markdown, mermaid_schema} ─────────────│
  │◀─── "9:{nodes}" ─────│                    │            │           │
```

### 2.3 降级策略

每个 Agent 调用都包裹 `try/except`，失败时不中断整条链路：

| 失败点 | 降级行为 |
| --- | --- |
| Profiler | 使用空 `StudentProfile(user_id="stud-01", weaknesses=[])` |
| Chat | 向客户端发送 `1:"Sorry, I encountered an error..."` |
| Writer | 静默跳过，不写 `generated_docs.json` |
| Resource | 返回 `fallback-1` 占位资源 |
| ChromaDB 不可用 | `chroma_client = None`，检索走 mock 分支 |

## 三、Spark 兼容层

讯飞星火 X2 的响应格式与 OpenAI Chat Completions 存在差异，PydanticAI 的 OpenAI provider 无法直接消费。`app/agents/orchestrator.py` 中的 `SparkCompatTransport` 解决了这个问题：

```python
class SparkCompatTransport(httpx.AsyncHTTPTransport):
    async def handle_async_request(self, request):
        response = await super().handle_async_request(request)
        content_type = response.headers.get("content-type", "")

        if "application/json" in content_type:
            # 补齐 OpenAI 协议要求的字段
            data = json.loads(response.content)
            data["id"]      = data.get("id") or data.get("sid") or "chatcmpl-spark"
            data["object"]  = data.get("object") or "chat.completion"
            data["model"]   = data.get("model") or settings.XUNFEI_SPARK_MODEL
            ...
        elif "text/event-stream" in content_type:
            # 解析 SSE chunk，改写 delta 格式
            ...
```

改写后，`spark_model` 就能以标准 OpenAI 模型的方式注入 PydanticAI 的 `Agent`，所有 Agent 共用同一个模型实例。

## 四、SSE 流式协议

`GET /api/chat` 返回 `text/event-stream`，每行格式为 `<前缀>:<JSON>`：

| 前缀 | 载荷 | 前端处理 |
| --- | --- | --- |
| `0` | 状态文本（字符串） | 顶部提示条，如「正在分析你的请求…」 |
| `1` | 对话内容增量（对象） | 追加到 AI 消息气泡 |
| `9` | `{nodes, description}` | 触发星图节点渲染 |

前端消费逻辑位于 `frontend/src/app/store.ts`。

## 五、知识库数据模型

三级树结构，与 Dify dataset 的映射关系：

```
Course (课程)
 └── Module (模块)
      └── Node (知识点)
           ├── Resource (资源文件：PDF / Markdown / 视频)
           ├── Quiz (测验题)
           ├── Code (代码任务)
           └── Presentation (演示文稿)
```

- **持久化**：SQLAlchemy 模型位于 `app/db/models.py`
- **同步**：`app/utils/kb_db.py` 负责 Dify ⇄ 本地双向同步
- **向量检索**：ChromaDB collection `dsa`，启动时若为空会用 `app/resources/*.md` 种子填充

Dify 轮询在 `main.py` 的 `lifespan` 中启动，每 30 秒同步一次（`poll_dify` 协程）。

## 六、遥测与实时推送

```
Agent 执行
   │
   ├─▶ set_agent_status("Profiler", "working")   ──┐
   ├─▶ log_token_usage("Profiler", 500)           ├─▶ Redis Pub/Sub
   └─▶ log_thought("...")                        ──┘   topic: agent_telemetry
                                                        │
                                          ┌─────────────┴─────────────┐
                                          │                           │
                              GET /api/console/ws              Web UI 控制台
                              （订阅并转发）                    （实时渲染）
```

实现位于 `app/utils/telemetry.py`，前端位于 `frontend/src/app/components/ConsoleView.tsx`。

## 七、异步任务链路

```
POST 触发重任务
   │
   ├─▶ Celery 发送（broker = Redis）
   │      返回 task_id
   │
   └─▶ 前端用 task_id 连 WS /ws/tasks/{task_id}
          │
          ├─ SUCCESS → 返回 result
          ├─ FAILURE / REVOKED → 返回错误
          └─ PROGRESS → 轮询转发进度（0.5s 间隔）
```

Worker 镜像（`Dockerfile.worker`）额外安装了 ffmpeg / cairo / pango，用于媒体渲染任务。

## 八、前端视图与路由

前端不使用 react-router，而是用 `App.tsx` 中的 `view` state 手动切换：

| view | 组件 | 说明 |
| --- | --- | --- |
| `canvas` | `CanvasFrame` + `PannableCanvas` | 知识星图画布（无限缩放拖拽） |
| `adaptive` | `AdaptiveView` | 自适应学习路径 |
| `notes` | `NotesView` | 笔记 / 知识图谱 / 标签 |
| `community` | `CommunityView` | 社区帖子（localStorage） |
| `starmap` | `StarMapView` | 星图百科（ChatGPT 式布局） |
| `console` | `ConsoleView` | 智能体控制台 |

全局状态集中在 `frontend/src/app/store.ts`（Zustand），另有 `store/adaptiveStore.ts` 与 `store/consoleStore.ts` 分域管理。
